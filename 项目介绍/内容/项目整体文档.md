4. Real-Finan 企业级多智能体金融分析系统 项目文档

   ## 项目简介

   Real-Finan 是一个基于 LangGraph 状态图编排的企业级多智能体金融分析系统。系统将一次完整的投研分析任务拆解为 7 个专业化 Agent 协同完成——从公司识别、多源数据融合、五维量化指标计算、管理层情绪深度分析，到多因子风险评分、合规审计，最终输出含 SWOT 拆解、情景推演（Base/Bull/Bear）和投资论点的机构级研究报告。LLM 层通过 ResilientLLMClient 实现了 DeepSeek API 为主、内置语义回退为兜底的容错架构，确保在无 API 密钥环境下仍可跑通完整流水线。系统对外暴露 FastAPI REST 接口，支持异步任务队列（Redis/RQ）和 PDF 财报上传解析。

   | 核心能力               | 说明                                                         |
   | ---------------------- | ------------------------------------------------------------ |
   | 7-Agent 协同分析流水线 | Supervisor→Retrieval→Quant→Psychologist→Critic→Replanner→Synthesizer 全链路自动化 |
   | 多源数据融合           | 实时行情（Yahoo/Alpha Vantage）+ PDF 财报解析（PyMuPDF）+ 内置样本数据库三重数据源 |
   | AST 安全表达式计算引擎 | 基于 Python AST NodeVisitor 的沙箱化公式求值器，杜绝代码注入，支持五维财务指标推导 |
   | LLM 容错与降级架构     | DeepSeek 主链路 + LocalFallback 语义匹配兜底，API 故障时自动切换，分析不中断 |
   | 机构级报告生成         | SWOT分析、Base/Bull/Bear情景推演、投资论点、同行对标、合规审计——11 章节结构化输出 |

   **路由逻辑（****`graph.py:21-35`****）：**

   - Retrieval 后若检测到附录数据缺口 → 触发 Replanner 补充检索；否则进入 Quant
   - Quant 后若数据不足无法计算 → 触发 Replanner；否则进入 Psychologist
   - Replanner 第 1 次触发：设置 `appendix_search_done=True`，重新进入 Retrieval
   - Replanner 第 2 次触发（`retries>=2`）：激活 `degraded_mode=True`，跳过检索直接进入 Synthesizer
   - Critic 后无论是否有合规发现 → 进入 Synthesizer（当前路由统一，但 Critic 的 `compliance_findings` 会写入报告第 10 章）

   ## 训练/执行流程

   本系统为推理时（inference-time）多 Agent 系统，无训练环节。完整分析流程如下：

   1. **入口**：`run_demo.py` CLI 或 `POST /api/v1/analyze` 接收 `query` + 可选 PDF 文件
   2. **PDF 预处理**（`documents.py:29-47`）：PyMuPDF 逐页提取文本，正则匹配公司名（14 个预置别名）和财务指标（Revenue/EBITDA/R&D），生成 `document_contexts`
   3. **系统初始化**（`graph.py:39-57`）：构建 LLM Client、MarketDataClient、SessionMemory、KnowledgeStore、AgentRuntime，编译 LangGraph StateGraph
   4. **Supervisor**（`agents.py:51-116`）：从 query 中提取公司名（三级策略：样本数据匹配→已知别名→LLM 提取→PDF 文件名回退），LLM 生成 task_brief + 分析维度 + 行业上下文
   5. **Retrieval**（`agents.py:121-189`）：遍历每家公司 → 融合样本数据 + 实时行情 + PDF 提取指标 + LLM 生成企业画像 → 写入 KnowledgeStore
   6. **Conditional Route**：检查数据完整性 → 缺数据则进入 Replanner 路径
   7. **Quantitative Analyst**（`agents.py:194-288`）：AST 安全求值器计算公式（EBITDA Margin/R&D Intensity/Operating Margin），集成实时 PE/市值/月回报/52周位置，LLM 生成同行对标综述
   8. **Psychologist**（`agents.py:293-310`）：双层情绪分析——规则引擎（正/负面词库命中计数）+ LLM 深度分析（整体语气/信心评分/关键主题/风险标记）
   9. **Critic**（`agents.py:315-387`）：五维度风险评分（财务/运营/市场/监管/供应链），因子驱动校准（利润率→财务风险，供应链等级→运营风险，情绪偏态→市场风险），LLM 合规审计意见
   10. **Replanner**（`agents.py:392-404`）：重试计数 + 降级判断（≥2 次触发 degraded_mode，跳过检索直接合成）
   11. **Synthesizer**（`agents.py:409-752`）：组装 11 章节 Markdown 报告，含 SWOT/情景推演/投资论点/图表数据，写入审计日志
   12. **输出**（`reporting.py:9-32`）：持久化 `_report.md` + `_audit.json` + `_state.json` 到 `outputs/` 目录

   ## FAQ

   **Q: 没有 DeepSeek API Key 能跑吗？** 能。`build_llm_client()` 在检测不到 `DEEPSEEK_API_KEY` 时，primary 设为 None，`ResilientLLMClient` 自动走 `LocalFallbackLLMClient`。这个 fallback 不是返回空字符串——它根据 prompt 中的关键词（`task_brief`/`executive summary`/`合规`）返回预设的中文分析文本，保证整个流水线跑通。CLI 运行 `python run_demo.py` 无需任何外部依赖即可看到完整报告输出。

   **Q: PDF 上传后系统能提取什么信息？** `documents.py:29-83` 做了三层提取：① 公司名——14 个中英文公司名关键词匹配（Apple/苹果/比亚迪/BYD/Tesla/腾讯等）；② 财务指标——正则匹配 Revenue/EBITDA/R&D 附近的数字，自动识别 billion/million/亿/万 单位并换算；③ 供应链信号——在全文搜索 `supply chain risk`/`供应链风险`/`logistics` 等关键词。提取结果会与实时行情数据融合。

   **Q: Quant Agent 的公式求值为什么用 AST 而不是** **`eval()`****？** `tools.py:13-69` 实现的 `SafeExpressionEvaluator` 继承 `ast.NodeVisitor`，白名单只放行 7 种 AST 节点（Expression/BinOp/Add/Sub/Mult/Div/Name/Constant 等），任何未授权节点（如 `Call`、`Attribute`）直接抛 `ValueError`。这样 `safe_execute_formula("ebitda / revenue", variables)` 等价于 `eval()` 的效果，但物理上不可能执行任意代码。

   **Q: 系统支持分析哪些公司？** 内置样本数据库（`data/sample_financial_data.py`）含 Apple 和 Microsoft 的 2025 完整财务数据（Revenue/EBITDA/R&D/Operating Income + 供应链信号 + 管理层引述）。14 家公司有预置股票代码映射（`market_data.py:8-23`）。其他公司依赖 PDF 上传提取或 LLM 知识库。

   **Q: 多 Agent 之间如何共享状态？** 所有 Agent 函数签名统一为 `(FinanceState) -> FinanceState`，通过 LangGraph StateGraph 的 `TypedDict` 状态在节点间传递。`FinanceState`（`state.py:12-43`）定义了 30+ 字段覆盖整个生命周期。AgentRuntime 在每个 Agent 函数内调用 `self.session_memory.save()` 保存 checkpoint，`self.reasoning_memory.record()` 记录审计事件。InMemorySaver 维护对话级状态持久化。
